## Patterns
- Per-test `seedPermission` + `try/finally` `deletePermission` is a stronger isolation pattern than `beforeAll`/`afterAll` when one test in the suite (e.g. the unauthorized case) requires the opposite seed state.
- Guarding E2E tests with a `credentialsPresent()` check + `test.skip` keeps the suite runnable in environments without Auth0/Supabase secrets.
- Targeting `getByRole("heading", { name: "HSPT Tutor", level: 1 })` rather than the literal `🎯 HSPT Tutor` string sidesteps emoji-in-separate-`<span>` rendering quirks.

## Anti-Patterns
- Don't add `data-testid` hooks to layout/component files for narrow access-tier specs — role + text queries suffice and avoid touching production code.
- Don't add the app slug to `APP_SELF_ENROLL_SLUGS` to ease test setup; it would defeat the gating assertion the spec is meant to prove.
- Don't claim acceptance criteria are met when env secrets to actually run the suite are absent — call out static-only verification explicitly (as done in the review notes).
