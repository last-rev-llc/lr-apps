## Patterns
- Pairing a server action test (input validation, normalization, auth scoping) with a component test (render states, form behavior) gives full coverage for a settings-page feature without needing e2e.
- Normalizing empty-string inputs (e.g. `alertEmail: ""` → `null`) inside the server action keeps the form simple and the DB clean — assert this explicitly in tests.
- Gating a single page with in-page `requireAccess` (rather than layout-level) is appropriate when only one route in a subtree needs a stricter tier than the rest.

## Anti-Patterns
- Don't ship UI components (e.g. `SslBadge`) with unit tests but no production consumer in the same batch — review correctly flagged this as INFO, but it leaves dead code if the consuming page is delayed.
- Don't claim AC coverage for items that depend on pages outside the batch scope (e.g. overview/per-client pages); mark them explicitly deferred in the PR.
