## Patterns
- When relocating an app out of a parent route group, audit the parent's hub page, sidebar/nav layout, and page tests for stale tile/link entries
- Mirror existing cleanup precedents (e.g. `ideas` removal) when removing tiles: drop from `EXPECTED_MODULES` and add a "does not render" negative-assertion test
- Use `pnpm create-app <slug> --name=... --subdomain=... --tier=... --template=... --permission=... --auth=...` for standalone mini-app scaffolds — registry, layout (`requireAppLayoutAccess`), and placeholder page land together

## Anti-Patterns
- Scaffolding a new top-level app without grepping for stale references to its prior location (route group tiles, sidebars, breadcrumbs)
- Updating `EXPECTED_MODULES` lists without adding the matching negative-assertion test that pins removal
