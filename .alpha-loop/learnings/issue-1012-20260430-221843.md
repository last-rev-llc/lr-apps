## Patterns
- When an issue references specific files (e.g. `docker/entrypoint.sh:151-173`), verify file existence with Glob before any implementation work — cheap check, prevents fabrication
- Returning a structured `review-batch.json` with `passed: false` + `requiredAction` is a clean way to surface operational/routing problems back to the orchestrator without producing dead code

## Anti-Patterns
- Do NOT fabricate files to satisfy acceptance criteria when the target tree is absent — creating `docker/entrypoint.sh` in a Next.js monorepo would violate CLAUDE.md (single deployable, no `docker/` tree) and produce dead code
- Do NOT mark a run "success" when zero acceptance criteria were met; the harness should distinguish "correctly declined (misrouted)" from "implemented and verified"

## Suggested Skill Updates
- Add a pre-flight check to the issue-implementation skill (or harness): for any issue that names file paths in its body, run Glob on those paths in the target worktree before starting; if all are missing, halt and emit a routing-mismatch report instead of attempting implementation
- Update run-status taxonomy: introduce a `declined_misrouted` status distinct from `success` so dashboards don't double-count routing failures as wins
