## What Failed
- Initial implementation shipped page.tsx as an unreachable `<h1>CRM</h1>` placeholder and contact-detail.tsx as a `null`-returning stub — the entire feature was dead code until review caught it.

## Patterns
- When `withSpan(name, attrs, fn)` attrs depend on validated body, pass `{}` initially and use `span.setAttribute(key, value)` after validation — functionally equivalent to upfront attrs.
- New API routes for an app slug should be paired with a routed page that actually mounts the consuming component; verify the route is reachable, not just that the handler exists.

## Anti-Patterns
- Leaving placeholder pages (`<h1>CRM</h1>`) and null-returning component stubs in a "completed" feature — tests pass but users see nothing.
- Asserting only on placeholder text in page tests; once the page becomes async/data-fetching the assertion masks regressions.
- Loose-typed fields in `types.ts` (`'high'|'medium'|'low'|string|null`) paired with strict zod enums elsewhere — the looser type silently accepts drift.
