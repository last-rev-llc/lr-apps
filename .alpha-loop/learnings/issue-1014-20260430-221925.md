## Patterns
- Before implementing against an issue spec, verify referenced file paths exist with Glob; if zero match, treat as a routing/scope problem rather than fabricating files
- Cross-check repo identity (CLAUDE.md, package.json, top-level dirs) against the issue's expected architecture early
- When rejecting an issue as out-of-scope, emit structured `verification` evidence (git diff summary, file searches, repo identity) so reviewers can confirm without re-investigating

## Anti-Patterns
- Do not scaffold `docker/`, `dashboard/server/`, or `dashboard/spa/` trees in lr-apps to satisfy a spec — CLAUDE.md forbids new top-level apps and this would create dead code
- Do not mark a run as "success" when the underlying issue is unresolved; misrouting is a routing failure, not a fix
- Do not let cross-issue context (a sibling issue mentioning a path) imply the path exists in the current repo
