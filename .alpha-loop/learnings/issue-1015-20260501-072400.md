## Patterns
- When acceptance criteria reference paths that don't exist in the target repo, surface the routing mismatch as info findings and pass the gate to halt retry loops, then flag operator action.
- Cross-check acceptance-criteria paths against the working tree before attempting implementation — saves cycles when batches are misrouted.

## Anti-Patterns
- Marking a run "success" when no source changes were produced conflates "gate passed" with "issue resolved" and pollutes learning data.
- Retrying inside the wrong repo when the host files (`docker/entrypoint.sh`, `dashboard/spa/`, `dashboard/server/`) are structurally absent — no amount of in-repo work can satisfy the criteria.

## Suggested Skill Updates
- Add a pre-flight check to the issue-execution skill that validates acceptance-criteria file paths exist (or have plausible parents) in the target repo before starting work; if mismatched, emit a routing-error status distinct from "success".
