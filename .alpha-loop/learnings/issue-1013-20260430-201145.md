## Patterns
- When test mocks supply a provider that production layouts forget to mount, the bug only surfaces at SSR/mount in production — verify provider mounting in the actual layout tree, not just in `renderWithProviders`.
- `React.createContext` at module scope requires `'use client'`; otherwise any RSC import path breaks `next build` with `createContext is not a function`.

## Anti-Patterns
- Accepting an issue whose acceptance criteria reference paths that don't exist in the target repo — verify file existence against the issue's repo before launching implementation.
- Relying on test-only providers (`renderWithProviders`) to validate i18n wiring without checking that the production layout itself mounts the provider.
