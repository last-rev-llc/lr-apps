## Patterns
- For pro-gated AI features, render four discriminated states (loading skeleton / success-with-sections / `feature_locked`→`UpgradePrompt` / error|rate_limited→Alert) keyed off the action's discriminated-union return — keeps the panel pure and trivially testable.
- Wire the new panel into its host page in the same change so reviewers can see it isn't dead code; tests-only proof is insufficient.

## Anti-Patterns
- Don't auto-bundle issues whose paths reference a foreign codebase (`dashboard/spa/...`, `dashboard/server/...`); validate path existence in the target repo before queuing them.
- Don't inline color hex/Tailwind palette values in panels — always pull through `@repo/ui` + theme tokens, even for "just a badge."
