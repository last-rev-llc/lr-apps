## Patterns
- When an issue's required paths don't exist in the repo, surface the mismatch immediately as a blocker rather than producing tangential work.
- Verifying file/path existence before planning implementation prevents wasted runs on cross-repo issues.

## Anti-Patterns
- Marking a run "success" when the issue was unimplementable in this codebase — status should be "blocked" or "skipped" with a clear reason.
- Conflating unrelated changes (a11y/mobile workflows, CLAUDE.md rewrite) with the requested issue scope.
- Generating "learnings" files for issues whose target codebase isn't present, instead of short-circuiting upstream.
