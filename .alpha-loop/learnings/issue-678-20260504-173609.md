## Patterns
- Idempotent pgsodium key provisioning via stable name lookup (`chatflow_targets_api_token_v1`) before `pgsodium.create_key`
- Defensive enum creation via `DO $$ BEGIN ... EXCEPTION WHEN duplicate_object THEN null; END $$` blocks for re-runnable migrations
- RLS row-table policies via `EXISTS` subquery against parent table (question_set_items → question_sets, chatflow_run_rows → chatflow_runs)
- Storage bucket per-user RLS keyed on `storage.foldername(name)[1] = auth.uid()::text`
- Audit-job CI workflows use mock UUID fallback (`00000000-0000-4000-8000-000000000000`) so dev server can boot without real secrets

## Anti-Patterns
- Placing test files under non-workspace directories (`scripts/__tests__/`) — they get silently skipped because no runner picks them up
- Treating proxy.integration.test.ts failures as in-scope when they're auth-hub regressions unrelated to the migration task at hand (status=failure should have triggered a focused diagnosis, not a generic test-fix retry)
