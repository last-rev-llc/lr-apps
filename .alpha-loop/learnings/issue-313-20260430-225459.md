## What Failed

## Patterns
- Versioned cache keys (`${CACHE_VERSION}` suffix) make global invalidation cheap and let the seed script invalidate by deleting a single key rather than scanning.
- Per-row try/catch around signed-URL generation in `listMyMemes` (drop failures, log error, return the rest) keeps a single bad storage path from breaking the whole list.
- `withSpan` + structured `@repo/logger` debug/error logs at action boundaries gives consistent observability without leaking PII (only userId, counts, and meme.id are logged).

## Anti-Patterns
- Documenting a cross-file contract ("seed script should call cacheDel") in a comment instead of wiring it up — comments rot and don't fail tests. If the contract matters for an acceptance criterion, encode it in code.
- Shipping read-side primitives (`listTemplates`, `listMyMemes`, `getMemeSignedUrl`) before the UI/registry that consumes them means they have no production caller and no end-to-end verification — fine when scoped to a single issue, but easy to forget the wiring later.
- `meme-generator-app.tsx` passes `template.imagePath` (storage path) directly as `img.src` instead of building the public bucket URL — dead code today (TEMPLATES has no imagePath rows) but a latent bug for whoever first wires `listTemplates()` into the UI.
