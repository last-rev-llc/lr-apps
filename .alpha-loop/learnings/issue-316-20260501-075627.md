## Patterns
- When adding a tier-gated feature flag, co-locate the enforcement test at the helper boundary (`enforce-feature-tier.test.ts`) rather than only at the action layer — keeps the test fast and isolated from billing/storage mocks.
- Use `vi.hoisted()` for module mocks that need to share state with the test body, especially when adding new mocks to an existing test file with cross-cutting fixtures (FormData builders, PNG byte helpers, store resets).

## Anti-Patterns
- Don't expand the in-memory query builder ad-hoc per test — the `makeQuery` chainable in `actions.test.ts` grew to ~150 lines supporting `select/insert/update/delete/single/maybeSingle/count`. If another action needs a new shape, extract a shared fake instead of forking.
