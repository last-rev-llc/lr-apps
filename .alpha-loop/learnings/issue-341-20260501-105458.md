## What Failed
- Initial `actions.ts` used `revalidatePath('/')` instead of the post-rewrite filesystem route, which would have silently broken list refresh after create/update/delete.

## Patterns
- For subdomain-routed apps, `revalidatePath` must use the Next.js filesystem route (`/apps/<slug>`), not the user-facing URL — proxy rewrites don't apply to revalidation.
- Reference sibling sub-apps (e.g. `command-center/cc-flags/lib/actions.ts`) for established conventions before inventing path constants.
- Tighten action tests to assert the exact `revalidatePath` argument, not just that it was called — catches silent path bugs.

## Anti-Patterns
- Using `'/'` or the user-facing subdomain URL in `revalidatePath` for subdomain-routed apps.
- Asserting `revalidatePath` was called without checking the path argument.
