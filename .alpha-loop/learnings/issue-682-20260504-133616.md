## Patterns
- New `@repo/*` packages should set `compilerOptions.lib: ["es2022", "dom"]` even when extending `@repo/config/tsconfig`, since the base only includes `es2022` and most package code uses Web APIs (fetch, Response, setTimeout).
- Per-subpath exports (`./client`, `./server`, `./ui`, `./schema`) plus `import "server-only"` on server entry points is the correct pattern for preventing server-only modules from leaking into client bundles.

## Anti-Patterns
- Relying on repo-wide `pnpm typecheck` to validate a new package — if the package has no typecheck script and apps/web's nextjs tsconfig pulls in dom via inheritance, the package's own type errors are masked. Run `tsc --noEmit` directly inside new packages.
- Declaring an issue complete without investigating pre-existing test failures in the same worktree; the proxy auth-hub failures should have been triaged as out-of-scope vs. regression before merge.
