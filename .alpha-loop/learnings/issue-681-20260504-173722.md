## Patterns
- For new required server-side env vars, validate format (UUID, URL, etc.) at the zod schema layer so misconfiguration fails at startup rather than at first use.
- CI workflows that don't need the real secret (audit/a11y jobs) should fall back to a syntactically valid mock value (`PGSODIUM_KEY_ID: ${{ secrets.X || '00000000-...' }}`) so the dev server boots without coupling unrelated jobs to secret availability.
- Idempotent provisioning scripts: look up by stable resource name before creating, and print the existing id on re-run so operators can paste it into env config either way.

## Anti-Patterns
- Adding test files under directories that aren't workspace packages — they look like coverage but never execute. Either move tests into a workspace package or wire a root-level script that runs them.
- Reporting "success" on a session step when the suite contains pre-existing unrelated failures — the proxy integration failures should have been triaged and either fixed or explicitly flagged before this issue's branch was considered done.
