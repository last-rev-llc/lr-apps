## Patterns
- When promoting a sub-route to a standalone app, update tests in lockstep: remove the old `__tests__/<feature>.test.tsx` and prune the feature from any "EXPECTED_MODULES"/label-list assertions in the parent layout/page tests.
- For canvas-using components under jsdom, stub `HTMLCanvasElement.prototype.getContext`/`toDataURL`/`toBlob` and `IntersectionObserver` in a `beforeAll` to avoid "Not implemented" noise leaking into assertions.
- Quota-exceeded UX can be verified by asserting the tier-specific upgrade copy (`quotaUpgradeCopyForTier()`) rather than the literal `<UpgradePrompt>` component — same user-visible behavior, less coupling to component identity.

## Anti-Patterns
- Don't insist on the literal component named in the spec (`<UpgradePrompt>`) when an inline Dialog renders the same upgrade copy — assert the user-visible text/behavior instead.
- Don't leave orphan tests pointing at a moved component path; deleting `command-center/__tests__/meme-generator.test.tsx` and `meme-generator/__tests__/render-meme.test.ts` was necessary because the source moved to the standalone app.
