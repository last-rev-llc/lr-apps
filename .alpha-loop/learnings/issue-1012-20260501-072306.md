## Patterns
- When acceptance criteria reference files absent from the repo, verify repo identity before attempting fixes
- Use `git diff origin/main` to confirm whether prior retries produced real source changes vs. only metadata files
- Mark misrouted batches as passed-with-info to prevent infinite retry loops requiring operator intervention

## Anti-Patterns
- Do not create placeholder files (e.g. `docker/entrypoint.sh`) just to satisfy acceptance criteria when the host repo lacks the surrounding infrastructure
- Do not commit `review-batch.json` or other orchestration artifacts to the repo working tree
- Do not retry within the wrong repo — escalate as a routing error instead

- Add a preflight check to the issue-implementation skill: verify all files referenced in acceptance criteria exist (or have a plausible parent directory) before starting work; bail with a routing-error signal if not
- Update review/code-review skill to short-circuit with `info` findings (not `critical`) when the batch targets a non-existent file tree, with explicit "operator must re-route" guidance
