## Patterns
- For server-only constants (`'use server'` modules) needed in Playwright runners, inline-copy with a comment explaining why is acceptable; importing would pull server code into the test runner.
- When asserting against a fallback list of N items, `expect(FALLBACK_PHRASES).toContain(text)` is more robust than matching one specific entry.
- `unauthPage`/`loggedInPage` fixtures + `seedPermission`/`deletePermission` helpers cover the full access-gating matrix without any new fixtures or DB helper files.

## Anti-Patterns
- Don't query by emoji or copy text in E2E assertions — testids on tabs/buttons/lists keep tests resilient to copy edits.
- Don't add the app slug to `APP_SELF_ENROLL_SLUGS` to make a test pass — that bypasses the real permission gate the test is meant to verify.
- Don't import from a `'use server'` module in a Playwright spec; duplicate the constant with a justifying comment instead.
