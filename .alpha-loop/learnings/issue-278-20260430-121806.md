## Patterns
- Two-phase decision logging: insert alert row first, then attempt delivery, returning a discriminated `AlertDecision` (sent/deduped/skipped) for caller observability.
- Per-user iteration with default-settings fallback: wrap `getAlertSettingsForUser` in try/catch and use defaults on rejection rather than failing the whole cron.
- Dedupe by querying for unacknowledged alerts of the same `(type, clientId)` before insert, not via DB unique constraint.

## Anti-Patterns
- Conflating "email send attempted" with "email delivered" in success counts — when send throws, decision is still `sent`, which muddles the `users/sent/deduped/skipped` log totals. Add `email_failed` discriminant if delivery metrics matter.
- Initializing fields that never get populated (`Bucket.expiring: []` at alerting.ts:55-56,67) — the per-user expiring set is computed separately, so the bucket field is dead weight.
