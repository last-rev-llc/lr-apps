## Patterns
- Use `[aria-label="..."]` wrapper containers as selector scopes when role/text could match multiple regions (filter rows vs. card content)
- Singular/plural badge assertions (`1 win` vs `2 wins`) double as filter-result count checks and pluralization-branch coverage in one assertion
- `test.skip(!credentialsPresent(), ...)` per-test guard plus no-op `beforeAll`/`afterAll` keeps suites green when env vars are absent

## Anti-Patterns
- Don't add `data-testid` hooks when role/text/aria-label selectors already disambiguate — the unit tests already prove these selectors are stable
- Don't co-locate permission-mutating cases (delete/re-seed) with cases that assume stable permission state in a single spec file
