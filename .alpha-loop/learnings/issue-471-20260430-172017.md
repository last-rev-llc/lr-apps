## Patterns
- For one-off audit scripts, documenting deviations via follow-up GitHub issues + PR comments preserves traceability when literal ACs cannot be safely satisfied (e.g., empty-in-dev ≠ abandoned-in-prod).
- Header comment marking a script as "slated for deletion" plus a tracked cleanup issue is a clean pattern for one-shot tooling.

## Anti-Patterns
- Brittle relative import path through `packages/db/node_modules/@supabase/supabase-js/dist/index.mjs` relies on pnpm symlink internals; should import via a workspace-resolved path or add `@supabase/supabase-js` directly.
- Shipping with a failing test suite without acknowledging it — even when failures appear unrelated, the run should explicitly call out and triage them rather than silently proceed to "complete."
