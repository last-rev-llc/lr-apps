## Patterns
- Splitting access/gating tests (which mutate permission state) from interaction tests (which assume stable state) into separate spec files prevents cross-test leakage.
- Guarding test bodies with `credentialsPresent()` skip + a hard throw in `userId()` keeps suites runnable in environments without E2E creds while still failing loudly when partially configured.
- Importing the production `wins.json` directly into the spec to derive expected counts/badges keeps assertions in sync with the data source.

## Anti-Patterns
- Don't bump permission roles beyond what the registry declares (registry permission for alpha-wins is `view`, not `edit`) — matches plan but worth flagging as an easy mistake.
- Don't add the slug to `APP_SELF_ENROLL_SLUGS` to make case 2 pass; that would defeat the gating test under `next start`.
