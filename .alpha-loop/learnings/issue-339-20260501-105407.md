## Patterns
- `revalidatePath` takes the Next.js filesystem route (`/apps/<slug>`), NOT the user-facing subdomain URL — verify by checking sibling apps like `command-center/cc-flags/lib/actions.ts`.
- Tightening tests to assert the exact `revalidatePath` argument (not just that it was called) catches path-mismatch bugs that otherwise silently break stale-data refresh.
- Three-action contact detail (Edit/Delete/Re-research) cleanly fits as one client component with local mode state — splitting into sub-components wasn't needed for ~600 lines.

## Anti-Patterns
- Don't pass the user-facing URL (`/`, `/contacts`) to `revalidatePath` in subdomain-routed apps — the proxy rewrite means the cache key is the rewritten filesystem path.
- Don't assert only `expect(revalidatePath).toHaveBeenCalled()` — assert the exact path argument so route-rewrite mistakes surface in tests.
