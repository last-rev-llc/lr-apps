## Patterns
- Promotion-to-subdomain cleanup = remove from `MODULES` array + remove from `EXPECTED_MODULES` test fixture + add negative `queryByText` assertion mirroring prior promotions (Ideas, Client Health).
- When a feature graduates to its own subdomain, delete the in-CC test files (`meme-generator.test.tsx`, `render-meme.test.ts`) since the standalone app owns those tests now.
- Hardcoded count literals (e.g. `"21 Routes"`) drift after promotions — pin to `MODULES.length` when straightforward to avoid the drift.

## Anti-Patterns
- Don't leave orphaned test files for promoted features in the source app — they become stale fixtures that mislead future readers.
- Don't keep a hardcoded module count next to a dynamic MODULES array; the two will diverge on every promotion.
