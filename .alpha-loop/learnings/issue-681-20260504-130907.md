## Patterns
- When promoting an env var from optional to required, audit every CI workflow that runs the app (dev server, build, tests) and add the var to each workflow's env block — startup-time validation breaks any context that boots the server.
- Pair idempotent seed scripts with a stable name/comment tag so re-runs return the existing id instead of creating duplicates; document the tag in the rotation doc.

## Anti-Patterns
- Declaring a run "complete" while the test suite has unresolved failures, even when the failures appear unrelated to the change. The harness should triage: confirm pre-existing vs. regression before exiting.
- Hard-failing on a missing env var without first verifying every CI entry point sets it would have shipped a broken main if the reviewer hadn't caught the workflow gap.
