## Patterns
- When gating a UI action behind a feature flag, render the trigger button in both states (gated + ungated) and branch the click handler to either open the modal or render `<UpgradePrompt feature="..." />` — keeps layout stable and avoids open/close shift.
- For modal action errors, type-narrow on custom error classes (`FeatureLockedError`, `RateLimitedError`) and surface distinct copy per class, including `resetAt` for retry-after.
- Reviewer should sanity-check that URL params produced by one feature (e.g. `?meme=<id>` from Library) are actually consumed by the destination page — query-string handoffs are easy to half-wire.

## Anti-Patterns
- Don't ship a "deep link into editor" affordance without verifying the destination reads `searchParams` and seeds initial state — the link looks correct but silently no-ops.
- Don't rely on AC checklists alone; explicit cross-feature integration tests (e.g. `meme-editor.test.tsx` preload case) catch wiring gaps that unit tests on each side miss.
