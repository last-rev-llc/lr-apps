## What Failed
- Initial `revalidatePath` used the user-facing URL `/` instead of the Next.js route key `/apps/crm`, which would have silently broken list refresh after mutations. Caught in review, not in tests.

## Patterns
- For subdomain-rewritten apps, `revalidatePath` must use the underlying filesystem route (`/apps/<slug>`), not the user-facing URL — convention established in `command-center/cc-flags/lib/actions.ts`.
- Test the exact revalidation path string in action tests (not just that `revalidatePath` was called) to catch wrong-path bugs.

## Anti-Patterns
- Don't assume `revalidatePath` operates on the URL the user sees — it operates on Next.js's internal route tree, which differs after proxy rewrites.
- Tests that only assert `revalidatePath` was called (without checking the argument) miss path-mismatch bugs entirely.
