## Patterns
- When a server action documents a cache key + invalidation contract via comment, treat that comment as a binding acceptance criterion for any writer (seed scripts, migrations, admin tools) and wire the invalidation explicitly.
- For Claude vision structured output, validate model-returned coordinates against image bounds before persisting — don't trust the schema alone.

## Anti-Patterns
- Documenting a cache-invalidation contract only in a comment in the reader (`actions.ts`) without enforcing it from the writer (the seed script) — easy to miss in review and produces stale-cache bugs in prod.
- Wiring storage `imagePath` values directly into `img.src` without composing the public URL from `NEXT_PUBLIC_SUPABASE_URL` — latent today because no live caller exercises it, but ships a tripwire for the next consumer.
