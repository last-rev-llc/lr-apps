## Patterns
- Idempotent enum creation via `DO $$ BEGIN ... IF NOT EXISTS ... END $$` blocks works cleanly for re-runnable migrations.
- ON DELETE RESTRICT for cross-table references where orphaning would lose audit history (vs CASCADE for parent-owned child rows).
- Row-level RLS via EXISTS subquery against parent run table keeps policies simple and consistent with question_set_items pattern from #678.
