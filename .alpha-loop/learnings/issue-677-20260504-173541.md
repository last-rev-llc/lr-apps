## What Failed
- 6 unrelated tests in `apps/web/__tests__/proxy.integration.test.ts` failed under "apps cluster host parsing" — `auth.apps.lastrev.com` paths (`/login`, `/signup`, `/unauthorized`, `/my-apps`, `/account`, and the no-prefix case) are no longer producing an `x-middleware-rewrite` header. Failure is in proxy/middleware behavior, not in the migration or pgsodium work landed by this issue.
- `scripts/__tests__/seed-pgsodium-key.test.ts` is orphaned — `scripts/` is not in `pnpm-workspace.yaml`, has no local vitest, and no root script invokes it, so the unit tests never run in CI.

## Patterns
- For new at-rest-encrypted columns: pair `create extension if not exists pgsodium` (idempotent) with a stable-named key (`<table>_<column>_v1`) seeded by an idempotent script that looks up by name before creating, and validate the resulting key id as a UUID in the app env schema so misconfiguration fails fast at boot.
- When introducing a required env var, update all four surfaces in one change: `lib/env.ts` schema, `turbo.json` `globalEnv`, `.env.example`, and every CI workflow (with a deterministic mock fallback for jobs that don't need the real value).

## Anti-Patterns
- Placing test files (`scripts/__tests__/*.test.ts`) outside any workspace package without wiring a root-level vitest invocation — they look like coverage but never execute.
- Failing the run on pre-existing unrelated test breakage (proxy auth-hub rewrites) rather than triaging up front; the migration/pgsodium work itself was complete and correct but the gate still flipped to failure.
