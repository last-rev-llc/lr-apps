## Patterns
- When acceptance criteria reference paths that don't exist in the repo, verify with Glob before any code attempt and emit a `fixableInThisRepo: false` verdict with explicit `requiredAction` for the operator
- Include `loopHistory` (commit SHAs of prior cycles) in the gate file so the orchestrator can detect futile retry loops
- Anchor the verdict in repo identity (CLAUDE.md architecture) so the misroute claim is auditable, not just "files missing"

## Anti-Patterns
- Marking a run "success" when no code changed and acceptance criteria are unmet — this corrupts retry-counter telemetry and hides systemic routing bugs
- Retrying a misrouted batch from inside the wrong worktree; each retry burns budget without any path to resolution
- Creating `docker/` or `dashboard/` directories in `lr-apps` to "host" the missing files would violate the registry-is-source-of-truth and single-app constraints in CLAUDE.md

## Suggested Skill Updates
- Add a pre-implementation guard to the issue-execution skill: if every file path in acceptance criteria fails a Glob existence check, halt and emit a misroute verdict instead of attempting changes
- Update the run-status reporter to distinguish `success` (code changed, criteria met) from `blocked-misroute` (no code changes possible) so retry loops surface to operators
