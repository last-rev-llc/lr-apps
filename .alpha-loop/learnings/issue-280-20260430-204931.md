## Patterns
- **AI server action shape**: `enforceFeatureTier` → rate-limit check → cache get → `generateObject` (or stub) → cache set → typed discriminated-union return (`{ ok: true, data }` | `{ ok: false, reason: 'feature_locked' | 'rate_limited' | ... }`).
- **Env-gated AI stub**: branch on `process.env.ANTHROPIC_API_KEY` and return a fixed-shape object that satisfies the same Zod schema — keeps callers and tests identical across modes.
- **Per-user rate-limit key**: scope Upstash key by `userId` (not IP) for authenticated server actions; tests can verify isolation by running 21 calls as user A then 1 as user B.

## Anti-Patterns
- Don't mock `generateObject` directly in tests — exercising the stub branch via unset `ANTHROPIC_API_KEY` is simpler and tests the actual fallback path users hit in dev.
- Don't add new env vars without updating both `turbo.json#globalEnv` AND `apps/web/lib/env.ts` — turbo will silently serve stale builds otherwise (per CLAUDE.md non-negotiable).
- Don't accept a batched issue list at face value — verify each issue's referenced paths exist in the current repo before starting (#1014/#1015 wasted cycles on a phantom `dashboard/` tree).
