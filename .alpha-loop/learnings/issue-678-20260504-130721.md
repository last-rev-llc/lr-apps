## Patterns
- When making an env var required (`z.string().uuid()` etc.), grep all CI workflows that start a dev/preview server and add a mock value — startup-time validation in `instrumentation.register()` breaks Playwright/audit jobs silently
- Pair every up migration with a `drop ... if exists` down so `pnpm lint`'s migration-pair guard stays green idempotently

## Anti-Patterns
- Declaring success without re-running `pnpm test` after the final commits — the test failure here predates the changes but was still surfaced by this run, and the loop should have caught + retried before marking complete
- Using plain string interpolation in seed SQL (even with a hard-coded constant) leaves no defense if the constant ever becomes dynamic — prefer `quote_literal` or parameterized queries from day one
