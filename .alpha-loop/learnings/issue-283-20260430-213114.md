## Patterns
- When changing log severity for a paging-sensitive code path (warn vs error), assert the exact log level in tests so future refactors can't silently re-page on-call.
- Partial-column upsert pattern preserves prior values on failure: omit the field entirely (don't write null) and assert `not.toHaveProperty` in tests.
- Inline a `// Issue #NNN:` comment at the load-bearing line when the WHY is a past incident — gives future readers a direct link to context without bloating commit archaeology.

## Anti-Patterns
- Shipping helper modules (badges, score functions) ahead of the page that consumes them leaves "tested but unwired" code that lingers as dead surface area until the consumer lands. If a consumer page isn't in the same batch, file a follow-up issue rather than merging the helper alone.
- E2E specs that name a feature in a comment (e.g. "AI summary (Stub)") without an assertion or `test.skip` create silent coverage gaps — either assert or explicitly skip with a TODO referencing the blocking issue.
