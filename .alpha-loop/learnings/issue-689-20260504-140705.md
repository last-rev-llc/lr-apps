- Review caught a missing env var registration (`PGSODIUM_KEY_ID`) and fixed it by updating both `turbo.json` globalEnv and `.env.example`.

## What Failed
- 6 pre-existing tests in `apps/web/__tests__/proxy.integration.test.ts` failed under "auth hub host parsing" — unrelated to issue #689 changes (run-store.ts is in `packages/ai-eval/`), but blocked the build because turbo runs all package tests.

## Patterns
- For atomic counter updates in Supabase, prefer `rpc(...)` to a stored procedure over `update ... set col = col + 1` round-trips; FakeSupabase can stub `.rpc()` directly for unit testing.
- Pair every new env var read (`process.env.X`) with a check that it appears in both `turbo.json` globalEnv and `.env.example` — this is a documented non-negotiable in CLAUDE.md.
- Test transactional create by asserting both the run insert AND row inserts fire, and that a row-insert failure rolls back the run (FakeSupabase can simulate this by failing the second `from(...).insert`).

## Anti-Patterns
- Don't assume sibling-package test failures are "yours" — proxy.integration.test.ts failures here were pre-existing on `auth.apps.lastrev.com` host parsing, unrelated to ai-eval changes. Verify via `git diff` scope before debugging.
- Don't ship code that depends on tables/RPCs that aren't in `supabase/migrations/` — even if tests mock them, runtime breaks. Either land the migration in the same PR or explicitly gate the feature.
- Don't add a new package that reads `process.env.X` without simultaneously registering X in `turbo.json` globalEnv — Turbo silently won't pass it to the build.
