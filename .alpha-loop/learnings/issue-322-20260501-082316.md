## What Worked
- Library page implemented all six acceptance criteria (grid, inline title edit, delete confirm, load-into-editor, empty state, layout-gated auth) with optimistic updates wired correctly.

## What Failed
- Initial implementation shipped a Load-into-editor link without the receiving side reading `searchParams`, so AC "preloads the editor with the saved meme's state" silently failed until review.

## Patterns
- When a feature spans two routes (library → editor), add an integration-style test that asserts the receiving route actually consumes the handoff param, not just that the sender emits it.
- Optimistic mutation pattern for delete/edit: snapshot prior state, apply update, await server, revert on throw — verified with explicit "restores on failure" test.

## Anti-Patterns
- Treating "Load into editor" as a navigation-only concern; producing a URL without verifying the consumer reads it is an easy AC miss.
- Asserting only on sender-side behavior (link href) without a paired test on receiver-side hydration.
