## What Failed
- Initial implementation shipped the new component but left the route page as an unreachable `<h1>CRM</h1>` placeholder and the detail panel as `return null` — the entire feature was dead code until the review pass.

## Patterns
- When porting a client component into a new app slug, also verify the route `page.tsx` actually mounts it and any sub-components (detail panels, modals) are fully ported, not stubbed.
- Span attributes only known after validation can be set via `withSpan(name, {}, async (span) => { span.setAttribute(...) })` instead of forcing them into the initial attrs map — functionally equivalent.

## Anti-Patterns
- Declaring an issue done based on the new file existing + tests passing, without checking that the routed page renders it. Tests targeting the new component pass even when the page never imports it.
- Leaving sub-components as `return null` stubs when the parent issue's AC explicitly requires their behavior (detail-panel toggle).
